# 단품 시험 (bring-up)

통합 펌웨어 전에 모터를 CAN 으로 하나씩, 그다음 두 개씩 구동해 보는 시험 스케치입니다.
모두 Teensy 4.1 CAN1(22 = CTX1, 23 = CRX1, 1 Mbps) → SN65HVD230 → DM-J4340P-2EC, MIT 모드입니다.

| 순서 | 폴더 | 내용 | 상태 |
|---|---|---|---|
| 1 | [`dm_single_test/`](dm_single_test/) | 모터 1개 활성화 · 위치 유지 · 정속 회전 · 정지 | **완료** — 피드백 수신, 정 · 역 회전, 회전 후 영점(0xFE) 확인 (2026-11 첫째 주) |
| 2 | [`dm_config_tool/`](dm_config_tool/) | CAN 으로 레지스터 읽기 · 쓰기 · 저장. 좌 · 우 모터 ID 설정, 1° 조그 | **완료** — L 1 / 0x11, R 2 / 0x12 쓰기 · 저장, 전원 재투입 후 유지 확인 (2026-11-09 ~ 16) |
| 3 | [`dm_dual_test/`](dm_dual_test/) | 모터 2개를 한 버스에서 500 Hz 로 동시 구동 (Kp 5 유지 · ±0.1 rad 이동) | **완료** — 2개 동시 피드백 · 방향 부호 확인. 다리 장착 후 `BENCH_SPIN_ALLOWED = false` |
| 4 | [`hip_step_test/`](hip_step_test/) | 다리 장착 상태 고관절 5° 계단 스윕 + 100 Hz CSV 로그 + 들기 모드(v2: Kp 80 · 중력보상 ff) | **진행 중** — 접힘 · 펼침 스윕, 토크 실측, 바퀴 접지 상태 접힘 · 펼침 성공 (2026-11-16). 들기 시작 ff 값은 측정 예정 |
| 5 | `odrive_can_test/` | ODrive 2축을 CAN2 로 토크 구동 | 예정 |

## 확인된 모터 설정값 (Teensy 로 레지스터 직접 읽음)

| 항목 | 값 | 코드 상수 |
|---|---|---|
| CAN ID / Master ID | L 1 / 0x11, R 2 / 0x12 (출하값 1 에서 변경, 저장 확인) | `CAN_ID` / `motors[].id` |
| PMAX | 12.5 rad | `P_MAX` |
| VMAX | **10 rad/s** | `V_MAX` (통합 계획의 8 에서 수정) |
| TMAX | 28 N·m | `T_MAX` |

이 세 값은 명령값을 CAN 프레임 정수로 바꾸는 범위입니다. 모터 레지스터와 코드가 다르면 모든 값이 비례해서 틀어집니다.
두 번째 모터도 `dm_config_tool` 의 `s` 로 같은 값인지 확인합니다 (`MISMATCH` 가 뜨면 멈추고 확인).

## 1. dm_single_test — 모터 1개

| 키 | 동작 |
|---|---|
| `e` | 활성화 (자유 모드, 토크 0) |
| `h` | 현재 위치 유지 (`e` 후 피드백이 와야 동작) |
| `a` / `b` | 정방향 / 역방향 회전 — 가속 → 정속 5 s → 감속 → 영점 재설정 → 브레이크 |
| `s` | 회전 중 감속 정지 |
| `d` | 비활성화 |

| 상수 | 기본값 | 의미 |
|---|---|---|
| `SPIN_SPEED` | 4.0 rad/s (≈ 38 rpm) | 목표 속도. 24 V 최대 무부하 52 rpm(5.45 rad/s) 이하 |
| `SPIN_HOLD_S` | 5.0 s | 정속 구간 시간 |
| `SPIN_ACCEL` | 2.0 rad/s² | 가속 · 감속률 |
| `SPIN_KD` | 1.0 | 걸리는 토크 = `SPIN_KD × (목표 속도 − 현재 속도)`. 0 이면 안 됨 |
| `MAX_SPIN_TORQUE` | 6.0 N·m | 넘으면 자동 비활성화 (정격 9 N·m) |

안전 로직: 피드백 끊김(활성화 직후 1 s, 이후 200 ms) · 모터 오류 코드 ≥ 8 · 로터 온도 60 °C · 위치 오차 1 rad(유지 상태) · 회전 중 토크 초과.

## 2. dm_config_tool — 좌 · 우 모터 ID 설정

같은 버스에 모터 두 개를 올리려면 ID 가 달라야 합니다. 출하 ID 가 같으므로 **한 개씩 연결해서** 설정합니다.

| | CAN ID (레지스터 8) | Master ID (레지스터 7) |
|---|---|---|
| 왼쪽 | `0x01` | `0x11` |
| 오른쪽 | `0x02` | `0x12` |

| 키 | 동작 |
|---|---|
| `s` | ID 1 ~ 16 스캔, 응답한 모터의 Master ID · CAN ID · Timeout · Mode · P/V/T MAX 출력, 코드 값과 비교 |
| `j` | 연결된 **한 개** 모터를 현재 위치에 잡고 `+` / `-` 로 1°씩 움직여 어느 모터인지 확인 (`c` 처음 위치, `q` 종료 · 비활성화). 시작 위치에서 ±10° 까지만, 토크 3 N·m 초과 · 피드백 끊김 시 자동 정지 |
| `L` | 연결된 **한 개** 모터를 왼쪽(1 / 0x11)으로 쓰고 저장 |
| `R` | 연결된 **한 개** 모터를 오른쪽(2 / 0x12)으로 쓰고 저장 |
| `t` | 연결된 한 개 모터의 CAN Timeout 을 2000(× 50 µs = 100 ms)으로 쓰고 저장 — 명령이 100 ms 끊기면 모터가 스스로 정지 |

순서

1. 왼쪽이 될 모터만 연결 → `s` 로 현재 값 확인 → `L` → 모터 24 V 껐다 켜기 → `s` 로 `CAN ID 0x1, Master ID 0x11` 확인
2. 왼쪽을 빼고 오른쪽이 될 모터만 연결 → `s` → `R` → 껐다 켜기 → `s` 로 `CAN ID 0x2, Master ID 0x12` 확인
3. 두 개 모두 연결 → `s` → `Scan done: 2 motors`, 두 모터 모두 PMAX · VMAX · TMAX `OK`
4. 모터에 왼쪽 / 오른쪽 라벨 붙이기

- `L` · `R` · `t` 는 스캔에서 정확히 한 개가 응답할 때만 실행됩니다.
- 레지스터 프레임(`0x7FF`, 읽기 `0x33` · 쓰기 `0x55` · 저장 `0xAA`)은 매뉴얼에 없고 Damiao SDK 기준입니다. 읽기는 확인됐고, **쓰기 · 저장은 전원을 껐다 켠 뒤 `s` 결과로 판단**합니다.
- 저장 실패 시(재부팅 후 값이 돌아감) Damiao 디버깅 툴(UART, GH1.25)로 같은 값을 씁니다 — [`host/dm4340p_setup.md`](../../host/dm4340p_setup.md).

## 3. dm_dual_test — 모터 2개 동시

`dm_single_test` 와 같은 명령에 대상 선택이 추가됩니다.

| 키 | 동작 |
|---|---|
| `0` / `1` / `2` | 대상: 둘 다(기본) / 왼쪽만 / 오른쪽만 |
| `e` · `h` · `d` | 선택한 모터 활성화 · 위치 유지 · 비활성화 |
| `+` / `-` | 유지 중인 위치를 0.1 rad(5.7°)씩 이동. 유지 시작 위치에서 ±0.35 rad(20°)까지만 |
| `c` | 유지 시작 위치로 복귀 |
| `a` / `b` / `s` | 벤치 회전 · 정지 (**다리에 달기 전에만**. 장착 후 `BENCH_SPIN_ALLOWED = false`) |
| `z` | 선택한 모터의 현재 위치를 영점으로 (비활성 또는 자유 상태에서만) |
| `x` | 전체 비활성화 (비상) |

단품 코드에서 바뀐 점

| | dm_single_test | dm_dual_test |
|---|---|---|
| 상태 | 전역 변수 하나 | 모터마다 `Motor` 구조체 |
| 피드백 | ID 1 만 받음 | 데이터 0번 바이트 하위 4비트(모터 ID)로 나눠 모터별 최신값 저장. 기다리지 않음 |
| 송신 주기 | 5 ms (200 Hz) | **2 ms (500 Hz)**, 한 주기에 활성 모터 전부 |
| 피드백 끊김 | 200 ms | **50 ms** (통합 계획 30 ms 로 가는 중간값) |
| 고장 처리 | 그 모터만 끔 | **한 쪽이 고장 나면 양쪽 다 끔** |
| 방향 | — | `dir` (왼쪽 +1, 오른쪽 −1 가정) — 같은 명령에 두 다리가 같은 방향으로 움직이게 |

확인 순서

1. `1` → `e` → `h` → `+` 로 왼쪽만 움직여 보고 `d`, 같은 방법으로 `2` 오른쪽
2. `0` → `e` → `h` → `+` 로 둘 다 — **두 다리가 같은 방향으로 움직이는지** 확인. 반대면 오른쪽 `dir` 부호를 바꿉니다
3. 상태 줄의 `cycle max` 가 2000 µs 보다 충분히 작은지 확인 (2 ms 안에 계산 · 송신이 끝나는지)

## 4. hip_step_test — 다리 장착 후 고관절 계단 스윕 · 토크 실측

`dm_dual_test` 의 유지 게인(Kp 5)으로는 다리 무게에 밀려 거의 움직이지 않아(0.1 rad 오차에 0.5 N·m) 따로 만든 시험 스케치입니다.
**다리 방향 + = 접힘** (2026-11-16 실측), 왼쪽 `dir` +1 · 오른쪽 −1 (거울 장착).

| 키 | 동작 |
|---|---|
| `0` / `1` / `2` | 대상: 둘 다(기본) / 왼쪽만 / 오른쪽만 |
| `e` | 켜기 — 토크 0 (FREE). **자세를 잡는 키가 아님** |
| `h` | 지금 자세를 기준 0° 로 잡고 유지 (Kp 30, Kd 2). 모터 영점은 건드리지 않음 |
| `g` / `n` | 접힘(+) / 펼침(−) 스윕: 0 → 5 → 10 → 15 → 20 → … → 0°, 10 °/s 램프 + 단계마다 1.5 s, 약 16 s |
| `p` / `r` | 스윕 일시정지 / 기준 0° 로 복귀 |
| `l` | CSV 로그 수동 on/off |
| `f` | **들기 모드** on/off — 게인을 30/2 → 80/3 으로 천천히 바꿈 (v2) |
| `]` / `[` | 펼침 방향 중력보상 ff ±0.5 N·m (다리당 0 ~ 8, 2 N·m/s 램프, 들기 모드에서만) (v2) |
| `s` | 상태 한 줄 (`rel` 각도, `tau`, `fb` 수신 프레임, 게인 · ff) |
| `d` / `x` / `c` | 선택 끄기 / **비상: 전부 끄기** / 에러 해제(꺼져 있을 때) |

- 스윕 중 100 Hz 로 `D,t_ms,L_ref,L_pos,L_vel,L_tau,R_ref,R_pos,R_vel,R_tau,ff` 출력 (각도 = 기준 대비 °, 토크 N·m, − = 펼침)
- 자동 정지 (양쪽 OFF): 피드백 50 ms 끊김 · 모터 에러 · |토크| > 14 N·m (v1 은 10) · 기준에서 22° 초과 · 추종 오차 10° 초과 · 70 °C 초과
- 로그 플롯: `python3 plot_log.py ~/logs/run1.txt` → `run1.png`(각도 · 토크 · 추종오차 3단), `run1.csv`, 단계별 평균 토크 표 (v1 로그도 읽음)
- 전체 절차 · 문제 해결 표: [`docs/electronics/05`](../../docs/electronics/05-hip-drive-test-procedure.md), 토크 해석: [`docs/electronics/06`](../../docs/electronics/06-hip-torque-gravity-comp.md)

## Khadas VIM4 (aarch64, Ubuntu 24.04)에서 올리는 방법

Arduino IDE 는 x86 용이라 aarch64 에서 쓸 수 없어 `arduino-cli` + `teensy_loader_cli` 를 사용합니다. 코드는 C++(Arduino) 입니다.

```bash
export PATH=$PATH:~/arduino/bin
arduino-cli core install teensy:avr           # 1회 (teensy:avr 1.62.0 확인)
arduino-cli compile --fqbn teensy:avr:teensy41 --output-dir build dm_dual_test
teensy_loader_cli --mcu=TEENSY41 -w -v build/dm_dual_test.ino.hex   # PROGRAM 버튼을 눌러 업로드
screen /dev/ttyACM0 115200                    # 종료: Ctrl+A, K, y
# 또는 로그를 남길 때 (2026-11-16 부터 사용)
picocom -b 115200 --echo --logfile ~/logs/run1.txt /dev/ttyACM0   # 종료: Ctrl+A, Ctrl+X
```

- `/dev/ttyACM0` 접근에는 `dialout` 그룹과 Teensy udev 규칙(`00-teensy.rules`)이 필요합니다.
- 명령은 셸이 아니라 `screen` 안에서 입력합니다.
- 업로드 후 Teensy 가 HalfKay 부트로더(USB ID `16c0:0478`)에 머물면 `/dev/ttyACM*` 이 생기지 않습니다. `lsusb | grep 16c0` 으로 확인하고 다시 업로드합니다 (시리얼은 `16c0:0483`).
- 파일은 노트북 PowerShell 에서 `scp` 로 옮기거나, Khadas 에서 이 저장소를 `git pull` 합니다.

## 지난 문제 · 남은 문제

- **해결** — 처음 `e` 후 `CAN frames received = 0`(no feedback)은 DM 모터 CAN 배선 문제였고, 배선 수정 후 피드백이 들어왔습니다.
- **해결** — CAN ID · P/V/T MAX 는 Teensy 로 레지스터를 읽어 확인했습니다 (위 표).
- **해결** — 회전 후 영점 재설정(`FF…FE`) 동작을 확인했습니다.
- **해결** — 모터 전원 투입 시 Teensy USB 가 끊기던 현상 (2026-11-09).
- **해결** — 레지스터 쓰기 · 저장(`0x55` · `0xAA`): 좌 · 우 ID 를 쓰고 전원을 다시 넣어도 유지됨 (2026-11-16 스캔).
- **해결** — 오른쪽 모터 `dir` 부호: −1 이 맞음. 같은 명령에 양쪽 다리가 같은 방향으로 접히고, 처짐 · 토크 부호도 같음 (2026-11-16).
- **해결** — `dm_dual_test` 첫 빌드 실패: Arduino 빌더가 함수 원형을 첫 함수 앞에 넣는데 그 위치가 `struct Motor` 보다 위였음 → 타입 정의 아래로 함수 이동 (429줄 판).
- **원인 확인** — 바퀴 접지 · 토르소 고정 상태에서 펼침이 −0.9° 에서 막힘: 펼 공간이 없었고, ff 없는 PD 로는 오차 × Kp 만큼(3 ~ 5 N·m)만 나와서. 고정 해제 + 들기 모드로 접힘 · 펼침 성공 (2026-11-16).
- **남음** — 모터는 전원을 켜자마자 LED 가 초록입니다 (매뉴얼 기준 초록 = 활성화). 동작에는 문제가 없었습니다.
- **남음** — Damiao 디버그 툴(UART)은 원인 미상으로 연결 안 됨. 설정 · 확인은 Teensy 레지스터 읽기 · 쓰기로 대신함.
- **남음** — DM CAN Timeout 은 아직 0(꺼짐). `dm_config_tool` 의 `t` 로 100 ms 설정 예정.
