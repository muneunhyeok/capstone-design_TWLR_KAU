## 1. 선회 (가장 쉬움 — 이미 절반 있음)

지금도 `j` `l` 로 `yaw_ref` 를 주면 양 바퀴에 `±yaw_ref·TRACK/2` 를 더하는 **개루프 선회**가 된다.
바닥 마찰 · 좌우 바퀴 차이로 실제 회전속도가 명령과 달라진다.

- **요레이트 PI 추가 (Teensy)**: `dv = (yaw_ref + Kp_ψ·(yaw_ref − gz) + Ki_ψ·∫(yaw_ref − gz)) · TRACK/2`. `gz` 는 이미 읽고 있음 (부호만 확인: 왼쪽으로 돌 때 +)
- 속도에 따라 `yaw_ref` 제한 (예: |v| > 0.3 m/s 이면 |ψ̇| ≤ 1 rad/s)
- 선회 원심 가속도 `v·ψ̇` — 0.3 m/s × 1 rad/s 면 0.3 m/s² → 바깥으로 약 1.75° 기울어지는 효과. 이 정도는 밸런싱이 버티고, 더 빠르게 돌 때는 3번(롤)으로 안쪽으로 기울여 보정

## 2. 스쿼트 (다리 높이 바꾸기)

### 2-1. 펌웨어에서 바꿔야 하는 곳 (중요)

지금 힙 홀드 목표 = `h` 를 누른 순간의 위치(`base`). 그리고 같은 `base` 기준 각도(`relDeg`)를 **두 군데**에 쓴다.

1. 힙 fault 판정 — `|relDeg| > 10°` 이면 힙 끔
2. CoM 오프셋 — `Δφ = DPHI_SIGN·relDeg + DPHI_AT_H` → `θoff(Δφ)`

그래서 `base` 를 그냥 움직여 스쿼트를 하면 Δφ 가 계속 0 으로 계산되어 CoM 보정이 틀어진다. 분리해야 한다.

```
base0   = h 누른 자세 (고정, Δφ 계산 기준)
q_cmd   = 다리 각 명령 [deg] (램프 제한 5~10 °/s)
목표    = base0 + dir·q_cmd           → MIT 위치 명령
fault   = |실제 − 목표| > 10°           (목표 기준으로 바꿈)
Δφ      = DPHI_SIGN·(실제 − base0) + DPHI_AT_H
```
새 명령: `'L' a=q_mean b=q_diff` (평균 = 스쿼트, 차이 = 롤). 파이썬은 키 `u`/`n` 같은 걸로 `q_mean` ±2°.

### 2-2. 높이에 따라 바뀌는 값 (model.py, 다리 하나)

| Δφ [°] (− 접힘 / + 펴짐) | −21.6 | −15 | −10 | −5 | **0 (현재)** | +5 | +10 | +15 | +20.5 |
|---|---|---|---|---|---|---|---|---|---|
| 정지 힙 토크 [N·m] | **9.48** | 8.10 | 7.33 | 6.74 | 6.30 | 5.98 | 5.73 | 5.51 | 5.27 |
| Kp 100 일 때 처짐 [°] | 5.4 | 4.6 | 4.2 | 3.9 | 3.6 | 3.4 | 3.3 | 3.2 | 3.0 |
| CoM 오프셋 θoff [°] | 14.4 | 10.5 | 8.5 | 7.2 | 6.2 | 5.3 | 4.3 | 2.9 | 0.6 |

- **접을수록 힙 토크가 커진다.** −21.6° 에서 9.48 N·m 로 DM4340P 정격 9 N·m · 펌웨어 fault 기준 10 N·m 에 붙는다 → **처음엔 −10° ~ +15° 안에서만**
- θoff 가 14° 넘게 변한다 → CoM 모델(θoff)이 틀리면 높이를 바꿀 때마다 앞뒤로 굴러감. 적분(KIv)이 흡수하긴 하지만 느림
- **중력보상(피드포워드) 켜기**: `TFF_ENABLE` + `'T'` 명령으로 `τ_ff = hip_torque_nm(Δφ)` 를 MIT 토크항에 더하면 처짐이 0 근처로 줄고 Kp 를 높이지 않아도 됨. 단 **Δφ 부호(DPHI_SIGN)를 바닥에서 먼저 확인** (거치대 위에선 몸무게가 안 실려 다리가 튐)
- 밸런싱 게인은 높이 영향이 작음 — CoM 높이 0.20 / 0.277 / 0.35 m 에서 LQR KTH 27.0 / 27.9 / 28.7, KW 3.86 / 4.65 / 5.35. 처음엔 게인 고정, KW 만 높이에 비례시키면 충분

### 2-3. 시험 순서

1. **거치대 위 (밸런싱 X)**: `'L'` 로 q_mean 을 ±5° 씩 램프 → 양 다리 같이 움직이는지, Δφ 부호, 토크 로그 확인
2. **고정 높이 밸런싱 3회**: 지금 방식 그대로 `e` → (−10°, 0°, +10° 자세) → `h` → `c` → `b`. 각 높이의 trim 값을 기록 → θoff 모델 검증 (trim 차이 ≈ θoff 차이여야 정상)
3. **밸런싱 중 천천히 스쿼트**: 5 °/s, ±5° → ±10°. 로그에서 `th_com`, `v_meas`, `hipT` 확인
4. 중력보상 켜고 3 반복

## 3. 롤 (좌우 다리 길이 차)

- 좌우 다리 각 차이 `q_diff` 로 몸통을 기울임. 몸통 롤 φ 에 필요한 바퀴 높이차 = `TRACK · tan φ` (트랙 0.488 m → 5° 에 42.7 mm)
- 다리 각 → 바퀴 높이(4절 링크 기구학) 맵 `h(Δφ)` 이 필요 → MATLAB/Simscape 기구학 모델에서 표로 뽑아 Teensy 에 넣기
- 롤 피드백: `bodyRoll()` 은 이미 계산 중. `q_diff = Kp_φ·(φ_ref − φ) + Kd_φ·(−roll_rate)` (느린 루프, 50 Hz 로 충분). 부호는 pitch 때처럼 먼저 손으로 확인
- 용도: ① 경사면에서 몸통 수평 유지 ② 선회 시 안쪽으로 기울이기 `φ_ref = atan(v·ψ̇ / g)`
- 롤을 주면 한쪽 다리는 더 접힘 → 위 표의 토크 증가 쪽을 넘지 않게 `q_mean ± q_diff/2` 를 −15° ~ +15° 로 제한

## 4. ROS 2 로 올리기

**지금은 ROS 2 가 아니다** (04 §1). 실시간 제어는 Teensy 에 두고, Khadas 의 `main_teensy.py` 를 ROS 2 노드로 바꾸는 방식을 권장한다.
(밸런싱을 ROS 2 / 파이썬으로 올리면 v2 때처럼 루프 지터 문제가 다시 생김.)

```
[Teensy]  twlr_bridge.ino  (지금 그대로 + 'L' 명령)
   │ USB 시리얼 (지금 프로토콜 그대로)
[Khadas, ROS 2 Jazzy — Ubuntu 24.04 arm64 공식 지원]
  twlr_bridge_node (rclpy)
    sub  /cmd_vel (geometry_msgs/Twist)        → 'V' linear.x, angular.z
    sub  /twlr/leg_cmd (height, roll)          → 'L'
    srv  /twlr/enable · /hold · /balance · /estop → 'E' 'H' 'B' 'D'
    pub  /imu/data (sensor_msgs/Imu) · /joint_states · /odom + TF · /twlr/status (diagnostic_msgs)
    10 Hz 로 'W' heartbeat (노드가 죽으면 Teensy 가 300 ms 후 바퀴 정지 — 지금과 같음)
  teleop_twist_keyboard / joy_node  → /cmd_vel   (블루투스 조이스틱)
  rosbag2  (CSV 로그 대체) · RViz2 + sim/twlr_description URDF
```
- 순서: 1(선회) · 2(스쿼트)의 `'L'` 명령까지 시리얼 프로토콜을 정한 뒤 노드를 만들면 메시지 설계를 한 번만 하면 됨
- 이후 SLAM(slam_toolbox) · Nav2 는 `/odom` + 라이다가 있어야 가능
