# 06 고관절 토크 실측 · 펼침이 어려운 이유 · 중력보상

2026-11-16 `hip_step_test` 실물 시험 결과와, 통합 펌웨어에 넣을 중력보상 설계 근거. 절차는 [05](05-hip-drive-test-procedure.md).

## 1. 실측 토크 = Kp × 추종 오차

고관절은 MIT 모드 `τ = Kp (q_des − q) + Kd (dq_des − dq) + τ_ff` 로 구동한다. ff = 0 이면 정지 상태 토크는 Kp × 오차로 정해진다.
Kp 30 N·m/rad → 1° 오차마다 약 0.52 N·m.

조건: 바퀴 접지 · 토르소 고정, Kp 30 · Kd 2 · ff 0.

| 상황 | 추종 오차 | 계산 (30 × 오차) | 실측 |
|---|---|---|---|
| `h` 유지 · 몸무게로 처짐 | ≈ 6° (0.105 rad) | 3.1 N·m | **2.8 ~ 3.4 N·m** |
| `n` 펼침 · 막힘 | ≈ 9° (0.157 rad) | 4.7 N·m | **4.5 ~ 5.1 N·m** |
| 한 줄 예: t = 3760 ms | L −9.10°, R −8.64° | L −4.76, R −4.52 N·m | L −4.79, R −4.49 N·m |

→ 모터와 전원(24 V 3 A 파워서플라이)은 명령한 만큼 정확히 힘을 냈다. 부족한 것은 **명령의 크기**다.

정역학 해석상 몸통을 들려면 다리당 **8.5 ~ 9.6 N·m** 가 필요하다. Kp 30 으로 이만큼 내려면 오차가 16 ~ 18° 벌어져야 하고,
그 전에 추종 오차 10° 안전 정지가 먼저 걸린다. 게인을 무작정 올리는 대신 **몸통 무게만큼을 ff(중력보상)로 미리 더한다.**

로그 끝부분에서 목표가 −10.1 … −10.9° 로 계속 내려가는 동안 실제 각도는 L −0.92°, R −1.42° 로 거의 그대로였고,
L 의 오차가 먼저 10° 에 닿아 `L: tracking error -10.0 deg` → `ALL DISABLED` 로 양쪽이 함께 꺼졌다 (보호 로직이 의도대로 동작).

### 속도 ±0.1 의 정체

DM4340P MIT 피드백 속도는 12비트(0 ~ 4095), 범위 ±VMAX(±10 rad/s). 한 칸 = 20 / 4095 ≈ 0.0049 rad/s ≈ 0.28 °/s.
칸 수가 짝수라 정확히 0 인 칸이 없어 정지 중에도 2047 / 2048(−0.14 / +0.14 °/s) 사이를 오간다.
→ **±0.3 °/s 안쪽은 0** 으로 보고, 그래프는 몇 샘플 이동평균. 실제로 움직인 구간에서는 L · R 속도 부호가 같았다(`dir` 정상).

## 2. 펼칠 때가 접을 때보다 어려운 이유

1. **중력이 한쪽만 돕는다** — 바퀴가 바닥에 닿아 있으면 토르소 무게가 계속 다리를 접는 쪽으로 누른다. 접을 때는 브레이크만, 펼 때는 토르소를 들어 올려야 한다.
2. **PD 만 쓰면 오차가 쌓여야 힘이 나온다** — 접을 때는 중력이 오차를 메워 주니 문제가 드러나지 않는다.
3. **가장 힘든 순간이 시작점에 몰린다** — 펼침은 토크가 가장 큰 접힌 자세에서 시작하고(정격 9 N·m 근처 · 초과), 접힌 쪽은 4절 링크 전달 효율도 떨어진다.
4. **감속기 마찰도 비대칭** — 40:1 효율을 약 80 % 로 보면 12 N·m 하중을 올릴 때 ≈ 15 N·m, 내릴 때 ≈ 9.6 N·m.
5. **부호 확인** — "접기는 되는데 펴기만 안 됨" 은 ff 부호가 거꾸로 들어갔을 때의 전형적인 증상이기도 하다. 오른쪽은 거울 장착이라 특히 확인.

처음 펼치지 못한 직접 원인은 두 가지였다: ① 토르소를 지그에 고정한 채 바퀴가 접지돼 **펼 공간이 없었고**, ② ff 없는 PD 라 **3 ~ 5 N·m 만** 나왔다.
→ 고정 해제(사람은 앞뒤 기울어짐만 잡음) + `hip_step_test` v2 들기 모드(Kp 80 · Kd 3 · ff)로 접힘 · 펼침 성공.

## 3. 중력보상 설계 (통합 펌웨어용)

### 각도별 유지 토크 LUT (다리 1개)

기준: CAD 기준자세(힙 높이 422 mm) = 0°, + = 접힘. 값은 고관절 스토퍼 검토 표의 하한값(M_eff 4.3 kg). 실측 ff 로 보정한다.

| 각도 [°] | −20 | −10 | 0 | 10 | 15 | 20 | 25 |
|---|---|---|---|---|---|---|---|
| τ_g [N·m] | 5.6 | 6.1 | 6.9 | 7.9 | 8.7 | 9.7 | 11.5 |

```cpp
// 다리 각도 규약: + = 접힘   (실측: L dir +1, R dir -1)
const float DIR[2] = {+1.0f, -1.0f};
const float LUT_DEG[] = {-20, -10,   0,  10,  15,  20,  25};
const float LUT_TAU[] = {5.6, 6.1, 6.9, 7.9, 8.7, 9.7, 11.5};

float gravityTau(float leg_deg);   // LUT 선형 보간, 양 끝은 끝값 유지

const float FF_TARGET  = 0.8f;   // 통합 펌웨어 config.h 의 FF_SCALE
const float FF_RAMP_S  = 0.5f;   // enable 후 0.5 s 동안 0 → 0.8
const float TAU_FF_MAX = 12.0f;

float ff_scale = min(1.0f, t_since_enable / FF_RAMP_S) * FF_TARGET;
for (int i = 0; i < 2; i++) {
  float leg_deg = DIR[i] * (pos[i] - zero[i]) * RAD_TO_DEG;
  float tau_leg = -ff_scale * gravityTau(leg_deg);              // 중력은 + (접힘) 쪽 → 보상은 − (펼침) 쪽
  float tau_ff  = constrain(DIR[i] * tau_leg, -TAU_FF_MAX, TAU_FF_MAX);   // 다리 좌표 → 모터 좌표
  sendMIT(id[i], p_des[i], 0.0f, KP, KD, tau_ff);
}
```

+10° 에서 τ_ff 가 약 6.3 N·m 를 맡으면 P 항이 채울 나머지는 1.6 N·m 정도 → 오차 약 3° 로 줄어 10° 보호에 걸리지 않는다.

- **목표각은 램프로** — 스텝 대신 0.1 ~ 0.2 rad/s 로 2 ms 마다 조금씩 (`p_des += constrain(p_goal − p_des, ±RATE·dt)`)
- **마찰 보상** — 움직이는 방향으로 조금 더 (펼칠 때 −, 접을 때 +). 크기는 아래 왕복 시험에서 구한다
- **I 항은 쓰지 않거나 아주 작게** — 정상오차는 ff 로 없애고, 바퀴가 들리거나 착지할 때의 와인드업을 피한다
- **보호 로직은 유지** — ff 를 넣은 뒤에도 10° 추종오차 정지가 걸리면 보상값이 모자라거나 부호가 틀렸다는 신호
- LUT 는 CAD 기준자세 기준이다. `h` 로 다른 자세에서 기준을 잡았다면 그 차이만큼 `leg_deg` 에 오프셋을 더한다

### 넣은 다음 확인 순서

1. **부호** — Kp 를 5 정도로 낮추고 τ_ff 만 준다. 한쪽씩 enable: 그 자리에 떠 있듯 버티면 정상, 주저앉으면 크기 부족, 튀어 오르면 부호 반대.
2. **램프 왕복** — 펼침 ↔ 접힘을 천천히 왕복하며 τ–각도 기록. 같은 각도에서 올라갈 때와 내려올 때 토크의 **평균 = 순수 중력 토크**, 차이의 절반 = 마찰. 이 값으로 LUT 를 고친다.
3. `hip_step_test` v2 의 들기 모드에서 **토르소가 받침에서 뜨기 시작하는 ff** 를 기록 → `FF_SCALE` 의 실측 근거.

## 4. 동작별로 게인이 달라야 하나?

동작마다 토크가 다른 것은 대부분 **게인이 아니라 ff 문제**다. ff 가 맞으면 PD 는 모델 오차 · 외란만 처리하므로 게인 하나로 넓은 자세를 버틴다.

- 밸런싱(바퀴) 쪽은 다리 길이에 따라 무게중심 높이 · 관성이 바뀌므로 **게인 스케줄링** — 다리 길이 3 ~ 5 점에서만 튜닝하고 사이는 선형 보간. 더 나아가 다리 길이별 LQR K 를 계산해 다항식 피팅(Ascento · RoboMaster 밸런스 보병 방식).
- 기립 · 밸런싱 · 넘어짐 복구처럼 성격이 다른 동작은 상태머신으로 나누고 모드별 게인 세트, 전환 시 0.2 ~ 0.5 s 램프.
- DM4340P 의 MIT 모드는 kp · kd · τ_ff 를 CAN 프레임마다 보내므로 실시간 스케줄링에 가장 잘 맞는다. 위치 · 속도 모드 내부 PID 는 레지스터 고정이라 불편하다. 고관절을 "PID 로" 하고 싶다면 MIT 모드의 PD + ff 에 상위(Teensy) 느린 I 항을 τ_ff 로 얹는 형태를 권장.
